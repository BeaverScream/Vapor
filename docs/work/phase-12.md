# Phase 12 — Design Decisions & Bug Fixes

Date: 2026-07-02

**Scope:** Implements the four resolved Phase 12 design decisions (VP-12.1, VP-12.2 — decisions only, no implementation rows) across six implementation items: the `session_resumed` event with granular resume error codes and the resume-failure UI transition gap (VP-12.3), capacity display + `ROOM_FULL` copy (VP-12.4), `peers[].isHost` (VP-12.5), the WebRTC syncPeers stale-state race (VP-12.6), closed data-channel reuse in `startOffer` (VP-12.7), and the timer double-countdown (VP-12.8). Backlog sources: BL-DOC-CONTRACT-DRIFT-01, BL-SIG-ROOMFULL-GHOST-01, BL-RESUME-DEAD-ROOM-UI-01, BL-WEBRTC-SYNCPEERS-RACE-01, BL-WEBRTC-CLOSED-CHANNEL-REUSE-01, BL-UX-TIMER-DOUBLE-COUNTDOWN-01.

**Ordering note:** VP-12.5 (peers type tightening) and VP-12.3 (SessionResumedPayload) touch the same `shared/payloads.ts` peers type — implement 12.5's shared-type change first or together with 12.3 so `SessionResumedPayload` inherits the final peer shape. VP-12.4's `reconnectingCount` is additive to the same payloads and is order-independent. VP-12.6/12.7/12.8 are independent of everything else.

| 7 | VP-12.3 | Decision | To classify "grace expired" as host vs guest, the `room`/`auth` lookup (`:582-587`) is **hoisted above** the disconnected/expired check (`:577-580`). Note: in the common case the host-grace timer destroys the room at the same instant `validUntil` passes, so `HOST_RECONNECT_WINDOW_EXPIRED` is reachable only in the timer-jitter window — the deterministic test must construct it with fake timers (advance clock past `validUntil` without firing the grace timer). |
