# Vapor Admin Dashboard Setup Guide

All configuration is done via a `backend/.env` file, which is loaded automatically by `dotenv.config()` in `backend/src/index.ts` on server startup.

---

## 1. Creating backend/.env

Create a file at `backend/.env`. This file is never committed to version control. The full set of supported variables is:

```env
# --- Auth (at least one block is required; admin routes are disabled if neither is set) ---

# Option A: Bearer token auth (for API clients, curl, scripts)
ADMIN_API_TOKEN=<random-string>

# Option B: HTTP Basic auth (for browser access — username + password prompt)
ADMIN_BASIC_USER=<username>
ADMIN_BASIC_PASS=<password>

# --- Email reports (all three required together; omit all three to disable email) ---
REPORT_EMAIL_FROM=<your-gmail-address>
REPORT_EMAIL_TO=<recipient-email>
GMAIL_APP_PASSWORD=<16-char-app-password>

# --- Optional overrides (have defaults) ---
# PORT=3001
# FRONTEND_ORIGIN=http://localhost:5173
# RECONNECT_TOKEN_PEPPER=<random-string>
```

**For local testing the simplest setup is Option B (Basic auth) with no email vars:**

```env
ADMIN_BASIC_USER=admin
ADMIN_BASIC_PASS=your-password-here
```

---

## 2. Auth Method Comparison

| | Bearer Token (`ADMIN_API_TOKEN`) | Basic Auth (`ADMIN_BASIC_USER` / `ADMIN_BASIC_PASS`) |
|---|---|---|
| Best for | API clients, curl, scripts | Browser-based human access |
| How to supply | `Authorization: Bearer <token>` header | Username + password in the dashboard credential form |
| Local testing | Works, but more cumbersome | Simpler — just a username and password |

Both methods can be configured simultaneously. A request succeeds if it satisfies *either* method. To require *both* simultaneously (higher security), see backlog item `BL-ADMIN-AUTH-AND-01`.

---

## 3. ADMIN_API_TOKEN Format

No specific format is enforced — it is compared as a plain string. Recommended: a cryptographically random hex or base64 string of at least 32 bytes.

Generate one with Node:
```
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

---

## 4. GMAIL_APP_PASSWORD Setup

`GMAIL_APP_PASSWORD` is **not** your Gmail account password and is **not** generated by Google Password Manager. It is a 16-character App Password issued by Google specifically for SMTP access.

Prerequisites:
1. 2-Step Verification must be enabled on the Google account used as `REPORT_EMAIL_FROM`.
2. Navigate to **myaccount.google.com → Security → 2-Step Verification → App passwords**.
3. Click "Create" (or "Add"), name it (e.g. "Vapor Backend"), and copy the 16-character code shown.
4. Set that code as `GMAIL_APP_PASSWORD` in `backend/.env`.

An App Password can be revoked at any time from the same page without affecting your account password.

## 5. Docker Memory Limit

The backend service is constrained to **256 MB RAM** in `docker-compose.yml`. `memswap_limit` is set equal to `mem_limit` to disable swap, matching bare-metal behavior and preventing the container from masking real-world OOM conditions by swapping to disk.

```yaml
# docker-compose.yml — backend service
mem_limit: 256m
memswap_limit: 256m
```

Baseline RSS at 0 rooms / 0 participants is approximately 40–60 MB, leaving ~200 MB of headroom. The admin dashboard's RSS card surfaces live memory usage so operators can correlate it against the configured cap. Bump to 512 MB only if the container starts being OOM-killed under real load.

## 6. Analytics CSV Store — Verification-Only Role

`CsvAnalyticsStore` is a **short-lived verification tool**, not the production analytics backend. Its purpose is to confirm schema correctness and catch obvious counter bugs (e.g. counters incrementing with 0 active rooms) before the Supabase migration.

**No Docker volume mount is configured for `backend/data/`.** The CSV lives inside the container filesystem and is wiped on `docker compose down`. This is intentional — the verification checks are shallow and can be done within a single running session:

1. Start the server with admin auth configured.
2. Wait up to 60 seconds for the startup baseline flush, then 30 minutes for the next row.
3. Open `backend/data/vapor-metrics.csv` — check that the header matches the `PeriodicRow` column order, all numeric fields parse correctly, and counters that should be zero (e.g. `roomsCreatedDelta` with no activity) are actually zero.

Once these checks pass, swap `CsvAnalyticsStore` for `SupabaseAnalyticsStore` in `backend/src/server.ts` (one line). The `AnalyticsStore` interface is already abstracted so no other callers change. `backend/data/` should remain in `.gitignore`.
